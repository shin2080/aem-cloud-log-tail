# AEM Cloud Log Viewer

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
![Node](https://img.shields.io/badge/node-%E2%89%A520-brightgreen)

로컬에서 돌리는 AEM as a Cloud Service 로그 뷰어.

여러 조직과 환경(dev/stage/prod)의 로그를 한 화면에서 실시간으로 따라가고,
지난 시간대를 뒤지고, 필요한 구간만 골라 파일로 저장한다.

Adobe Cloud Manager 웹 UI 에서 로그를 보려면 다운로드 링크를 눌러 `.gz` 를 받고,
풀고, 에디터로 여는 일을 반복해야 한다. 이 도구는 그 사이를 없앤다 —
브라우저에서 바로 흘러가는 로그를 보고, 눈으로 고른 만큼만 집어간다.

> **Adobe 의 공식 도구가 아니다.** 개인이 만든 것이고 Adobe 와 무관하다.
> Cloud Manager API 를 **읽기만** 한다.

## 무엇을 하나

- **실시간 tail** — 환경·서비스별 로그를 SSE 로 흘려 보여준다. 레벨 필터, 검색, 일시정지
- **시간대 조회** — 지난 구간(최대 7일, Adobe 보존 한도)을 훑어 조건에 맞는 줄만 모은다
- **창 나누기** — 같은 환경의 author·publish·dispatcher 를 최대 4개까지 나란히
- **묶기** — 같은 예외 수백 건을 한 줄로 접는다
- **내보내기** — 선택한 구간만 log/json/csv 로. 출처가 파일 첫머리에 박힌다
- **마스킹** — 이메일·토큰·카드번호·주민번호·공인 IP 를 버퍼에 들어가기 전에 가린다
- **계정과 감사 로그** — 조직·prod 접근을 계정별로 나눠 주고, 누가 무엇을 봤는지 남긴다
- **한국어 / 영어**

### 지켜야 할 것

이 도구는 **여러 조직의 client secret** 과 **prod 로그의 실사용자 데이터**를 다룬다.
설계가 그 위에서 정해졌고, 판단이 갈릴 때 여기로 돌아온다.

1. **로그를 영구 저장하지 않는다** — DB 에는 설정·계정·감사 기록만. 로그 본문은 메모리 링버퍼에만 있다
2. **로컬 전용** — `127.0.0.1` 바인딩이 기본, DB 는 SQLite 파일 하나
3. **읽기 전용** — Cloud Manager 쓰기 API 를 부르는 코드를 넣지 않는다
4. **자격증명은 `.env` 에만** — `clientSecret` 을 만지는 파일은 `server/config/env.ts` 와 `server/adobe/ims.ts` 둘뿐이다
5. **조직 경계는 서버에서 강제** — 프론트가 보내는 org 식별자를 믿지 않는다

설계 배경은 [SPEC.md](SPEC.md), 실환경 측정 결과는 [docs/findings.md](docs/findings.md) 에 있다.

## 요구 사항

- **Node.js 20 이상**
- **Adobe Cloud Manager 접근 권한** — 아래 [자격증명 만들기](#adobe-자격증명-만들기) 참고
- macOS / Linux / Windows. 빌드에 네이티브 모듈(`better-sqlite3`, `@node-rs/argon2`)이
  섞여 있어 `npm install` 에 빌드 도구가 필요할 수 있다

## 빠른 시작

```bash
git clone <이 저장소>
cd aem-cloud-log-tail
npm install
cp .env.example .env
```

`.env` 를 열어 최소 세 가지를 채운다.

```bash
openssl rand -hex 32     # 이 결과를 SESSION_SECRET 에
```

| 항목 | 값 |
|---|---|
| `SESSION_SECRET` | 위 명령 결과 |
| `ADMIN_EMAIL`, `ADMIN_INITIAL_PASSWORD` | 최초 관리자 (비밀번호 8자 이상) |
| `ORG_1_*` | 조직 하나 이상 — 다음 절에서 만든다 |

그리고,

```bash
npm run build
npm start
```

http://127.0.0.1:7300 이 열린다. 첫 부팅에 관리자 계정이 만들어지고 콘솔에 안내가 뜬다.
`ADMIN_EMAIL` 과 `ADMIN_INITIAL_PASSWORD` 로 로그인하면 **비밀번호 변경을 요구한다.**
바꾼 뒤 `.env` 의 `ADMIN_INITIAL_PASSWORD` 는 지운다 — 그 값은 첫 부팅에만 쓰인다.

값이 빠졌거나 형식이 틀리면 **무엇이 왜 틀렸는지 알려주며 즉시 종료한다.**
반쯤 뜬 채로 나중에 실패하게 두지 않는다.

## Adobe 자격증명 만들기

가장 많이 막히는 지점이라 따로 적는다. 조직마다 한 번씩 한다.

### 1. Developer Console 에서 프로젝트를 만든다

1. [developer.adobe.com/console](https://developer.adobe.com/console) 에 로그인한다.
   **오른쪽 위에서 조직이 맞는지 확인한다** — 조직이 여러 개면 여기서 자주 틀린다.
2. **Create new project**
3. **Add API** → **Cloud Manager** 를 고른다
4. 인증 방식은 **OAuth Server-to-Server** 를 고른다
   (JWT 는 2025년에 폐기됐다. 이 도구는 JWT 를 지원하지 않는다)

### 2. 제품 프로필을 고른다

API 를 붙이면 제품 프로필을 고르라고 한다. **Cloud Manager - Developer**
또는 그 이상(Deployment Manager, Business Owner)이면 된다.
로그를 읽는 데 필요한 것은 다음 셋뿐이고, Developer 프로필이 다 가지고 있다.

```
GET /api/programs                                          프로그램 목록
GET /api/program/{id}/environments                         환경 목록
GET /api/program/{id}/environment/{id}/logs?days=N         로그 파일 목록과 링크
```

**쓰기 권한은 필요 없다.** 배포·파이프라인을 건드리는 코드가 이 저장소에 없다.

### 3. 값 네 개를 `.env` 로 옮긴다

프로젝트의 **Credentials → OAuth Server-to-Server** 화면에 있다.

```dotenv
ORG_1_KEY=acme                      # 내가 정하는 식별자. 아래 주의사항을 읽는다
ORG_1_LABEL=ACME 코퍼레이션          # 화면에 보일 이름
ORG_1_IMS_ORG_ID=XXXXXXXX@AdobeOrg  # Credential details 의 Organization ID
ORG_1_CLIENT_ID=...                 # Client ID
ORG_1_CLIENT_SECRET=...             # Client Secret (Retrieve client secret)
ORG_1_SCOPES=openid,AdobeID,...     # 화면에 표시된 scope 문자열
```

`ORG_n_SCOPES` 는 **화면에 보이는 대로 복사한다.** Developer Console 은
`openid, AdobeID, read_organizations, ...` 처럼 쉼표 뒤에 공백을 넣어 보여주는데,
IMS 는 그 공백을 거부한다. 이 도구가 읽으면서 공백을 지우므로 그대로 붙여넣으면 된다.

조직을 더 넣으려면 `ORG_2_*`, `ORG_3_*` 으로 잇는다.
`ORG_n_LABEL` 이 비면 거기서 스캔을 멈춘다.

> **`ORG_n_KEY` 는 한 번 정하면 바꾸지 않는다.** 이 값이 DB 의 `user_orgs.org_key` 와
> 조인된다. 바꾸면 기존 계정의 조직 접근 권한이 전부 끊긴다.
> 자격증명만 갈아끼우는 것도 위험하다 — 캐시된 환경 목록이 옛 조직 것인데 호출은
> 새 자격증명으로 나가 Adobe 가 403 을 준다. (지문을 남겨 자동으로 다시 받지만,
> 되도록 키도 같이 바꾼다.)

### 4. 연결을 확인한다

```bash
npm run phase0 -- --org acme
```

`--org` 는 `.env` 의 `ORG_n_KEY` 값이다. 생략하면 첫 조직을 쓴다.
토큰을 받고, 프로그램·환경을 훑고, 로그 링크를 확인한 결과를
`docs/findings.md` 에 덮어쓴다. 여기서 실패하면 화면에서도 실패한다.

## 쓰는 법

### 로그 고르기

로그인하면 **환경 목록**이 뜬다. 조직이 여럿이면 위쪽 버튼으로 고른다.

목록이 비어 있으면 **Cloud Manager 에서 새로고침**을 누른다. 환경 목록은 30분 캐시된다 —
매번 부르면 조직 하나 여는 데 수십 콜이 나가 레이트 리밋에 걸린다.

환경 행의 **서비스 확인**을 누르면 그 환경이 실제로 가진 로그가 나온다.
로그 이름 버튼이 **실시간 tail**, 옆의 `⌕` 가 **시간대 조회**다.

### 실시간 tail

- 헤더에서 **레벨**(ERROR / WARN+ / 전체 / 직접 고르기)과 **검색어**를 건다.
  `.*` 를 켜면 검색어를 정규식으로 읽는다
- **일시정지**를 누르면 화면이 멈추고 그동안 온 건수가 버튼에 쌓인다. 폴링은 계속 돈다
- 바닥에 붙어 있으면 새 로그를 따라가고, 위로 스크롤하면 멈추고
  "새 로그 N건" 버튼이 뜬다
- 헤더 오른쪽 숫자는 버퍼에 든 줄 수, 그 옆은 **가장 최근 로그의 나이**다.
  3분을 넘으면 색이 바뀐다 — 트래픽이 없거나 파이프라인이 밀린 것이다

로그는 **메모리에만** 있다. 세션당 50,000줄 / 128MB 링버퍼이고 넘치면 오래된 것부터
밀려난다. 밀려나면 화면이 알려준다. 붙잡아 두려면 북마크한다.

### 시간대 조회

위에서 구간을 고르고 **조회**를 누른다. 프리셋은 5분 / 10분 / 30분 / 1시간 / 6시간 / 24시간.

**10분 이하를 고르면 "마지막 2분은 아직 비어 있을 수 있다"** 고 알려준다.
로그가 스토리지에 도착하기까지 실측 2분쯤 걸린다. 짧은 구간에서는 그 대부분이
아직 안 온 시간이라, 결과가 비었을 때 도구가 고장난 줄로 오해하기 쉽다.

- Adobe 는 **7일치만 보관한다.** 구간이 그 밖이면 그렇다고 말해준다
- 결과가 200,000줄을 넘으면 멈춘다. 구간을 좁힌다
- KST 새벽 0~9시는 **전날 UTC 파일**을 봐야 한다. 이건 알아서 처리한다

### 골라서 내보내기

줄을 누르면 시작점이 잡히고, **Shift + 클릭**으로 끝을 잡으면 구간이 선택된다.
이게 이 도구의 핵심 조작이다 — 파일 전체를 받는 게 아니라 눈으로 보고 필요한 만큼만 집는다.

선택하면 아래에 바가 뜬다. **복사**는 클립보드로 (슬랙·이슈에 붙일 때),
**선택 구간 내보내기**는 파일로 나간다.

| 포맷 | 내용 |
|---|---|
| `log` | 원본 라인 그대로 |
| `json` | JSONL — 줄마다 `LogEntry` 하나 |
| `csv` | ts, level, pod, thread, logger, message |

파일 첫머리에 **조직·환경·구간·필터·요청자**가 박힌다. 며칠 뒤에 받은 사람도
이게 어디서 나온 것인지 알 수 있다. 마스킹은 이미 적용된 상태로 나간다.

## 지원하는 로그

파서가 있는 것만 열린다. 목록에도 열 수 있는 것만 나온다.

| 서비스 | 로그 |
|---|---|
| author / publish | `aemerror` `aemaccess` `aemrequest` |
| dispatcher | `aemdispatcher` `httpdaccess` `httpderror` |
| cdn | `cdn` |

`aemerror` 와 `httpderror` 는 **스택트레이스를 한 덩어리로 묶는다.** 나머지는
한 줄이 곧 한 건이다. access 계열에는 레벨이 없어서 **HTTP 상태로 매긴다** —
5xx 는 ERROR, 4xx 는 WARN.

## 마스킹

버퍼에 **들어가기 전에** 적용된다. 화면·내보내기·복사 어디로도 원본이 나가지 않는다.
`MASKING_ENABLED=false` 로 끌 수 있지만, prod 를 볼 거면 켜 둔다.

이메일 · Bearer 토큰 · Basic 인증 · 비밀번호류 쿼리 파라미터 · 카드번호 ·
주민등록번호 · 공인 IP(사설 대역은 그대로 둔다).

실제 로그로 맞추느라 오탐 방어가 몇 개 들어가 있다 — 13자리 epoch ms 를 주민번호로,
JSON 소수를 카드번호로 읽던 것들이다. 규칙을 건드리면 `server/parse/mask.test.ts` 를 같이 본다.

## 여러 환경 같이 보기

`/tail` 과 `/search` 모두 **+ 창 추가** 로 최대 4개까지 나란히 띄운다.

**창 추가는 지금 보고 있는 환경 안에서만 고른다** — author 옆에 publish, 그 옆에
dispatcher. 창을 나눠 보는 이유가 '같은 환경의 다른 계층에서 한 요청이 어떻게
흘러갔나' 이므로, 여기서 다른 환경까지 늘어놓으면 고를 것만 많아진다
(환경이 24개인 조직이 실제로 있다). 다른 환경은 환경 선택 화면에서 새로 연다.

시간대 조회에서는 **구간을 모든 창이 공유한다** — 비교의 요점이 '같은 시간대의
다른 로그' 이므로 창마다 구간이 다르면 나란히 놓는 의미가 없다.
레벨·검색어는 창마다 따로 둔다. `조회` 를 누르면 모든 창이 함께 돈다.

- 창마다 **레벨·검색·일시정지가 따로** 논다. 글자 크기와 타임존만 공유한다
- 화면 폭에 따라 좌우/상하를 자동으로 고르고, 직접 고르면 그 선택을 기억한다
- **URL 이 곧 화면 상태다.** `?p=org:env:service:log` 가 창 하나에 대응하므로
  새로고침하거나 링크를 넘겨도 같은 조합이 열린다
- 4개로 제한한 이유는 브라우저가 같은 호스트로 가는 연결을 6개쯤으로 묶기 때문이다.
  창 하나가 SSE 연결 하나를 계속 물고 있어서, 더 열면 나머지 API 호출이 굶는다

## 뷰어에서 쓸 수 있는 것

- **묶기** — 같은 사건을 하나로 접고 `×N` 을 단다. 숫자·UUID 가 달라도 같은 것으로 본다.
  같은 예외가 수백 번 반복될 때 화면을 되찾아 준다
- **★ 북마크** — 표시해둔 줄은 링버퍼에서 밀려나도 남는다. 로그가 메모리에만 있으므로
  중요한 줄을 붙잡아 두려면 이게 필요하다
- **시간축 분포** — 버퍼 전체의 레벨별 분포. 막대를 누르면 그 시각으로 이동한다.
  스크롤로 훑는 것보다 '언제 터졌나' 를 훨씬 빨리 찾는다
- **필터 저장** — 자주 쓰는 레벨·검색어 조합을 이름 붙여 둔다. tail 과 조회 양쪽에서 쓴다

묶기·북마크·분포는 창 헤더의 `⋯` 메뉴에 있다. 헤더가 좁아 자주 쓰는 것만 밖에 뒀다.
북마크는 브라우저에 남으므로 새로고침해도 유지된다 — 다만 `seq` 는 서버 세션마다
0부터 다시 매겨져서, 서버를 재시작하면 별이 다시 켜지지는 않는다.
저장해둔 줄 자체는 '북마크만 보기' 로 계속 볼 수 있다.

## 한국어 / 영어

화면 오른쪽 위 계정 메뉴, 그리고 로그인 화면에서 바꾼다. 로그인 전에도 바꿀 수
있어야 해서 두 곳에 둔다 — 화면이 읽히지 않는 사람이 메뉴에 들어갈 수는 없다.

처음 열 때는 브라우저 설정을 따르고(한국어가 아니면 영어), 한 번 고르면
그 브라우저에 기억한다. `<html lang>` 도 함께 바꾼다.

**서버 오류 메시지도 같이 옮긴다.** 요청마다 `X-Lang` 을 실어 보내고 서버가
그 말로 만들어 돌려준다. 헤더가 없으면 한국어다 — curl 로 두드릴 때 지금까지와
같다. 서버 콘솔과 감사 기록은 옮기지 않는다. 그쪽은 서버를 돌리는 사람이 보는
것이라 언어를 섞을 이유가 없다.

로그 내용 자체는 옮기지 않는다. 그건 AEM 이 쓴 글이다.

## 계정 운영

계정은 관리자가 발급한다. **회원가입 엔드포인트는 없다.**

- 우상단 계정 메뉴 → **계정 관리** / **감사 로그** (admin 만 보인다)
- 계정을 발급하면 **임시 비밀번호가 화면에 한 번만** 나온다. 서버에 저장되지 않으니
  그 자리에서 전달한다. 잃어버리면 '비번 초기화' 로 다시 발급한다
- 조직 접근과 **prod 열람은 따로 준다.** prod 로그에는 실사용자 데이터가 섞인다.
  prod 권한이 없으면 환경 목록에서 prod 가 아예 빠지고, ID 를 직접 넣어도 404 다
- 권한을 줄이면 그 계정의 **기존 세션이 즉시 끊긴다**

되돌릴 수 없는 실수는 서버가 막는다 — 자기 계정 비활성화·강등·삭제, 마지막 관리자 제거.

감사 로그는 **조회만 된다.** 삭제 API 를 만들지 않았다. 다만 무한히 쌓이게 두지는 않는다.
`AUDIT_RETENTION_DAYS`(기본 365일)가 지난 기록은 부팅 때와 하루 주기로 정리한다.
0으로 두면 영구 보관한다. 누가 흔적을 지우지 못하게 하는 것이 목적이므로
나이만 보고 기계적으로 정리하는 경로만 둔다.

## 조직을 추가할 때

`.env` 에 `ORG_n_*` 를 넣는 것만으로는 화면에 안 나온다. 두 가지가 더 필요하다.

1. **서버 재시작.** `tsx watch` 는 `server/` 만 감시하고 `.env` 는 안 본다.
   부팅 로그의 `조직 N개 로드` 로 확인한다
2. **계정에 권한 부여.** `/api/orgs` 는 `.env` 가 아니라 계정의 접근 권한을 기준으로 준다.
   최초 관리자 시딩은 계정을 만들 때 한 번만 조직을 붙이므로, 나중에 추가한 조직은
   **계정 관리에서 직접 체크해야 한다**

환경 선택 화면이 이 두 상태를 알려준다 — `.env` 에는 있는데 권한이 없는 조직,
권한은 있는데 `.env` 에서 사라진 조직을 각각 배너로 띄운다.

## 외부 접근

기본은 `127.0.0.1` 바인딩이라 이 기기에서만 열린다. 밖에서 쓰려면 셋 중 하나를 고른다.

이 도구가 무엇을 들고 있는지 먼저 생각한다 — 여러 조직의 **client secret**, 그리고
prod 로그의 **실사용자 데이터**다. 로그인 화면이 열리는 범위가 곧 그 데이터의 노출 범위다.

### 1. 본인 기기에서만 (권장)

Tailscale 같은 메시 VPN 을 쓴다. 공인 IP·포트포워딩·인증서가 필요 없고, 인터넷에는
아무것도 노출되지 않으며, 네트워크 계층에서 암호화된다.

```bash
tailscale ip -4          # 100.x.x.x 확인
```

```dotenv
HOST=100.x.x.x
```

폰·노트북에서 `http://100.x.x.x:7300` 으로 붙는다. 추가로 할 일이 없다.

### 2. 같은 사무실/집 네트워크

```dotenv
HOST=0.0.0.0
```

그 네트워크의 **모든 기기**가 로그인 화면을 볼 수 있다. 평문 HTTP 라 같은 망에서
패킷을 보면 비밀번호와 세션 쿠키가 그대로 보인다. 신뢰할 수 있는 망에서만 쓴다.

### 3. 인터넷 (팀 공유)

앞단에 TLS 를 끝내는 리버스 프록시(Caddy/nginx)를 두고:

```dotenv
HOST=127.0.0.1
SESSION_COOKIE_SECURE=true
TRUST_PROXY=true
```

프록시만 앱에 접근하도록 `127.0.0.1` 을 유지한다. `TRUST_PROXY=true` 는 프록시가
`X-Forwarded-For` 를 **덮어쓰는** 경우에만 켠다 — 그러지 않으면 헤더를 조작해
감사 기록의 IP 를 속일 수 있다.

이 경우 다음도 함께 검토한다:

- 로그인 실패 제한은 프로세스 메모리에 있다. 단일 프로세스면 동작하지만,
  여러 인스턴스로 늘리면 무력화된다
- 비밀번호 최소 길이가 8자다 (`server/auth/password.ts`). 인터넷에 열 거면 올린다
- 고객사가 자기 prod 로그를 이 경로로 내보내는 데 동의했는지 확인한다

바인딩이 loopback 이 아니면 부팅 때 무엇이 열렸고 무엇이 빠졌는지 콘솔에 찍는다.

## 모니터에 띄워두고 쓰기 (PWA)

설치형 앱으로 열어 상시 모니터에 걸어두는 쓰임을 염두에 두고 만들었다.
Chrome 주소창의 설치 아이콘, 또는 ⋮ → "앱 설치" 로 창 장식 없이 띄운다.

**https 가 필요하다.** 서비스워커는 보안 컨텍스트에서만 돌기 때문에
`localhost` 가 아니면 평문 HTTP 로는 설치되지 않는다 (기능은 그대로 동작하고,
설치형으로만 안 열린다). Tailscale 이면 이렇게 붙인다:

```bash
tailscale cert $(tailscale status --json | jq -r .Self.DNSName | sed 's/\.$//')
```

그리고 `SESSION_COOKIE_SECURE=true` 로 바꾼다.

### 캐시에 무엇이 남는가

서비스워커([`web/public/sw.js`](web/public/sw.js))가 캐시에 넣는 것은 **앱 껍데기뿐이다** —
HTML 과 해시가 박힌 JS/CSS. `/api/*` 는 아예 가로채지 않는다.

이건 편의가 아니라 이 도구의 전제를 지키는 문제다. 로그 본문은 메모리에만 두기로
했는데, 서비스워커가 API 응답을 캐시하면 고객사 prod 로그가 평문으로 디스크에 남고,
로그아웃해도 안 지워지고, 같은 기기의 다음 사람이 앞사람 캐시를 읽는다.
Workbox 의 흔한 `runtimeCaching` 레시피가 정확히 그 일을 하기 때문에 직접 썼다.
로그아웃하면 남은 껍데기 캐시까지 비운다.

### 상시로 켜두면 달라지는 것들

| | 기본값 | 왜 |
|---|---|---|
| `SESSION_TTL_HOURS` | 12 | **유휴** 기준이다. 화면이 10분마다 서버를 두드려 계속 연장한다 |
| `SESSION_MAX_HOURS` | 168 | 연장의 천장. 이 주기로는 사람이 가서 다시 로그인해야 한다 |
| `TAIL_BUFFER_MAX_LINES` | 20000 | **세션당** 이다. 창 넷이면 넷 다 이만큼 쥔다 |
| `TAIL_BUFFER_MAX_BYTES` | 32MB | 위와 같다. 24시간 켜두면 이게 상시 점유 메모리다 |

무기한 로그인을 만들고 싶으면 `SESSION_MAX_HOURS` 를 올리는 대신,
**키오스크 전용 계정**을 따로 발급하고 prod 열람 권한을 주지 않는 편이 낫다.
상시 로그인된 브라우저는 그대로 상시 유효한 자격증명이다.

### 알아서 버티는 것들

- 서버가 재시작하거나 세션이 유휴 정리되면 로그의 seq 가 0부터 다시 시작한다.
  화면은 세대(generation)가 바뀐 것을 보고 쌓아둔 것을 버리고 다시 채운다 —
  이걸 안 하면 "연결됨" 인 채로 새 로그만 조용히 안 들어온다
- 화면이 렌더 중에 터지면 무엇이 났는지 보여주고 스스로 새로고침한다
  (되풀이되면 기다리는 시간을 늘린다)
- 새 배포가 올라오면 서비스워커가 알아채고 한 번 새로고침한다.
  보고 있던 창은 URL 에 들어 있어 그대로 돌아온다
- 서명 URL 이 만료되기 전에 미리 다시 받는다. 만료된 URL 로 받은 오류 응답을
  로그로 착각해 먹지 않는다
- 열려 있는 스트림도 15초마다 권한을 다시 본다. 계정을 끄거나 조직 권한을
  회수하면 이미 열린 창도 끊긴다

### 남는 것

화면 앞을 지나가는 사람 전부가 관객이다. 마스킹은 IP·이메일·주민번호·카드번호·
Bearer 토큰을 잡지만 한국 휴대폰 번호, 한글 이름·주소, 접두어 없는 JWT,
고객사 고유 식별자는 규칙이 없다. 상시로 띄울 거면 그 로그에 맞춰
[`server/parse/mask.ts`](server/parse/mask.ts) 의 규칙을 한 번 더 채운다.

서버는 표시용 기기에서 돌리지 않는 편이 낫다 — `.env` 에 모든 조직의
client secret 이 평문으로 있다.

## 문제가 생기면

**로그인 화면에서 "이메일 또는 비밀번호가 올바르지 않다"**
`ADMIN_INITIAL_PASSWORD` 는 **첫 부팅에만** 쓰인다. 이미 계정이 만들어진 뒤에
`.env` 를 고쳐도 반영되지 않는다. `data/app.db` 를 지우면 처음부터 다시 시딩되지만
계정·감사 기록이 함께 날아간다.

**환경 목록이 비어 있다**
**Cloud Manager 에서 새로고침**을 누른다. 그래도 비면 `npm run phase0 -- --org <키>`
로 자격증명부터 확인한다.

**Adobe 가 403 을 준다**
둘 중 하나다. (1) 그 자격증명에 해당 환경 권한이 없다 — Developer Console 의
제품 프로필을 확인한다. (2) `ORG_n_KEY` 는 그대로 두고 자격증명만 바꿔서, 캐시된
환경 목록이 옛 조직 것이다 — 새로고침하면 풀린다.

**조직을 추가했는데 안 보인다**
[조직을 추가할 때](#조직을-추가할-때) 를 본다. 서버 재시작과 계정 권한 부여가 둘 다 필요하다.

**tail 이 열렸는데 아무것도 안 온다**
트래픽이 없거나, 고른 레벨에 해당하는 줄이 없다. 헤더의 마지막 로그 나이를 본다.
3분을 넘어 있으면 그 환경에 요청 자체가 없는 것이다. 레벨을 '전체' 로 넓혀 확인한다.

**조회 결과가 비었다**
구간이 짧으면 마지막 2분은 아직 도착하지 않았을 수 있다. Adobe 보존은 7일이라
그 밖의 구간은 읽지 못하고, 그런 날짜는 화면이 따로 알려준다.

**날짜가 하루 어긋나 보인다**
로그는 UTC 로 쌓인다. KST 새벽 0~9시는 전날 UTC 파일에 들어 있다.
화면은 KST/UTC 를 토글할 수 있고, 조회는 이 경계를 알아서 처리한다.

**`npm install` 이 네이티브 모듈에서 실패한다**
`better-sqlite3` 와 `@node-rs/argon2` 를 빌드한다. macOS 는 Xcode Command Line Tools,
리눅스는 `build-essential`, 윈도우는 Visual Studio Build Tools 가 필요할 수 있다.

## 개발

```bash
npm run dev       # 서버 (7300)
npm run dev:web   # Vite (7301, /api 는 7300 으로 프록시)
```

브라우저는 http://127.0.0.1:7301 로 연다.

```bash
npm run typecheck   # 서버 + 웹
npm test            # 단위 테스트
npm run build       # dist/ 로 빌드
```

`.env` 를 고쳤으면 **서버를 재시작한다.** `tsx watch` 는 `server/` 만 본다.

### 문자열을 고칠 때

`web/src/i18n/strings.ts` 와 `server/i18n/messages.ts` 두 곳이다.
`en` 은 `Record<StringKey, string>` 이라 키를 빠뜨리면 타입 검사에서 걸리고,
자리표시자가 어긋나거나 안 쓰는 키가 남으면 테스트가 잡는다.

비밀번호 최소 길이 같은 숫자는 서버가 내려준다 (`/api/auth/me` 의 `minPasswordLength`).
화면에 박아두면 정책을 바꿨을 때 안내와 검증이 따로 논다. 정하는 곳은
`server/auth/password.ts` 한 군데뿐이다.
